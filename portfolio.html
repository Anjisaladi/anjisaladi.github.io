Travel Feed

A full-stack travel social app where users document trips as day-by-day timelines of stops, each with photos, captions, and GPS coordinates. Built solo in six weeks — from Supabase schema design through to Play Store submission with 20+ beta testers. Features glassmorphism UI with dynamic Pexels backgrounds, OTP authentication, photo uploads, a social feed, and GDPR-compliant account deletion via an Edge Function.

Process

How it came together

"How did you handle the full stack solo?"
Used Claude as a pair programmer throughout — prompting for architecture decisions, debugging obscure EAS build errors, writing Row-Level Security policies, and generating Play Store assets. The AI handled the long tail of plumbing so I could stay focused on product decisions.
"What was the hardest part?"
Getting the Supabase Edge Function for account deletion to authenticate correctly. The JWT verification toggle in the dashboard was on, which meant the anon key wasn't being accepted. Tracked it down through the function logs and fixed it by calling getUser(token) directly.
"How did you learn what you didn't know?"
Iterated fast — ran into npm peer dependency conflicts, WSL installation issues, and Play Console policy requirements all in the same week. Each blocker became a learning loop: read the error, understand the system, fix forward.
"What would you do differently?"
Set up the EAS environment variables before the first build instead of debugging a blank-screen crash on a real device. Also, git-initialize the repo before configuring EAS — it saves the EAS_NO_VCS=1 workaround.
